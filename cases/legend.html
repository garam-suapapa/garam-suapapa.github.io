CASE 01

충전 방식을 나눠
보유 구조를 명확하게

스태미너가 최대치에 도달하면 충전이 멈추는 구조는, 보유량을 비우기 위해 접속 시간을 맞춰야 한다는 부담으로 이어질 수 있습니다. 자동 충전과 추가 충전을 분리해 최대치 이후에도 충전분을 보유할 수 있는 구조를 설계했습니다.

설계의 중심은 충전 수단을 한 최대치에 묶지 않고, 서로 다른 보유량으로 보여주는 것이었습니다.

화면에서는 충전 스태미너와 예비 스태미너의 보유량, 다음 충전까지의 시간, 충전 중지 상태를 각각 확인할 수 있습니다. 실제 충전·차감 우선순위는 공개된 화면만으로 확인할 수 없어 이 사례에 추가하지 않았습니다.

설계 목표

최대치 이후의 충전분을 별도로 보유할 수 있게 해 접속 부담을 줄이고 편의성을 높이는 것을 목표로 했습니다. 지표 변화는 확인 자료가 없어 성과 수치로 기재하지 않았습니다.

CASE 02

다른 유저의 편성을
도전의 출발점으로

신규 유저가 팀 구성 기준을 알기 어려우면 콘텐츠 진입 장벽이 높아질 수 있습니다. 전투 데이터 스냅샷을 바탕으로 추천 편성을 보여주고, 유저가 해당 구성을 자신의 팀에 복사할 수 있도록 설계했습니다.

INPUT

전투 데이터 스냅샷

실제 도전에 사용된 편성, 전투력, 속성과 역할 구성을 추천 정보로 제시합니다.

ACTION

추천 편성 복사

추천 사례를 확인한 뒤 복사 버튼으로 자신의 편성에 적용할 수 있는 흐름입니다.

설계 목표

편성 기준을 모르는 유저에게 실제 구성 사례를 제공해 콘텐츠 도전을 시작하기 쉽게 만드는 것을 목표로 했습니다. 추천 선정 조건과 예외 규칙은 추가 확인이 필요합니다.

SCOPE

전체 담당 범위

메인 콘텐츠

  • 모험·요일 던전·무한의 탑·로그라이크 콘텐츠
  • 전용 코인과 재화 상점을 연결한 보상 구조
  • 길드 레이드·출석·상점을 포함한 길드 시스템

시즌 이벤트

  • IP 외전 스토리 기반 시즌 구성
  • 일정 주기로 콘텐츠를 여는 시즌 스케줄
  • 미니게임과 이벤트 전투 보상 루트

시스템

  • 스태미너 충전 구조
  • 맵 트리거 기반 텔레포트
  • 전투 데이터 기반 추천 팀 편성
